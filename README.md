# Blossie

Blossie is a static editorial journal built with Astro. It is a small, deliberate publication about personal style, beauty, home, wellness, culture, and the texture of ordinary days.

The site is intentionally front-end only: articles are Markdown files, the search index is generated at build time, and the newsletter form is an honest design demo that sends and stores nothing.

## Stack

- [Astro](https://astro.build/) 7 with TypeScript and static output
- Astro content collections for articles
- Custom CSS with design tokens, light/dark/system themes, and no UI framework
- `@fontsource` self-hosted fonts: Cormorant Garamond (display) and DM Sans Variable (body/UI)
- `@astrojs/sitemap`, `@astrojs/rss`, and Astro's built-in image optimization
- Minimal client-side JavaScript for theme choice, navigation, filtering, search, sharing, and reading progress

## Quick start

```bash
npm install
npm run dev
```

Open the local URL printed by Astro (usually `http://localhost:4321`).

### Commands

| Command           | Purpose                                      |
| ----------------- | -------------------------------------------- |
| `npm run dev`     | Start the development server with HMR        |
| `npm run build`   | Type-check content and build the static site |
| `npm run preview` | Preview the production build locally         |
| `npm run check`   | Run `astro check` for type and template errors |

The build output is written to `dist/`.

## Pages and routes

- `/` — home page with the current cover story, recent stories, editor's picks, topics, and newsletter demo
- `/journal/` — all stories with live topic filtering, text filtering, and sorting
- `/journal/[slug]/` — article pages with reading progress, share/copy actions, and related stories
- `/topics/` — all six subjects
- `/topics/[topic]/` — a subject hub with its stories
- `/about/` — editorial statement and production notes
- `/archive/` — stories grouped by year and month
- `/search/` — full-text search over titles, categories, tags, standfirsts, excerpts, and article bodies
- `/404.html` — custom not-found page
- `/rss.xml` — RSS 2.0 feed
- `/sitemap-index.xml` — sitemap index generated by `@astrojs/sitemap`
- `/robots.txt` — crawl policy and sitemap reference
- `/search-index.json` — generated search index consumed by `/search/`

## Writing a new story

1. Add a Markdown file to `src/content/articles/`. The filename becomes the URL slug:

   ```text
   src/content/articles/a-slow-sunday.md
   ```

2. Start the file with frontmatter that matches the schema in `src/content.config.ts`:

   ```yaml
   ---
   title: 'A Slow Sunday'
   standfirst: 'A short deck that introduces the story.'
   excerpt: 'A one- or two-sentence summary used on cards, in search, and in the RSS feed.'
   category: 'Lifestyle'
   pubDate: 2026-10-28
   author: 'The Blossie Editors'
   cover: '../../assets/images/story-slow-sunday.jpg'
   coverAlt: 'A descriptive alternative text for the cover image.'
   coverCaption: 'Optional caption shown beneath the cover image.'
   coverCredit: 'Photography via Pexels'
   featured: false
   editorsPick: false
   tags: ['slow living', 'weekends']
   ---
   ```

3. Write the article body in Markdown. Headings, blockquotes, lists, links, and images are styled by the article prose styles. A short excerpt is used on cards and in search; the standfirst is the longer deck under the title.

4. Add the cover image to `src/assets/images/`. Imported images are optimized by Astro at build time.

5. Run `npm run build` to validate the schema, generate the article route, and regenerate the search index and RSS feed.

### Categories and topics

The allowed categories are fixed in the content schema:

`Lifestyle`, `Beauty`, `Personal Style`, `Wellness`, `Home & Living`, `Culture`.

Each category maps to a topic in `src/data/topics.ts`. To add a new subject, add its definition and image import there, extend the category enum in `src/content.config.ts`, and add a topic image. The topic route is generated automatically.

### Featured stories

- `featured: true` promotes a story to the home page cover slot. Only one story should be featured at a time.
- `editorsPick: true` adds a story to the editor's picks section.
- If no story is marked featured, the newest story is used.

## Images

Photography is stored locally in `src/assets/images` and rendered through Astro's `<Image>` and `getImage()` APIs. This provides responsive `srcset` output, modern formats, and dimensions to reduce layout shift.

The article social image is generated from the cover at 1200 × 630 when an article page is built. The site-wide fallback social image is `public/og-default.jpg`.

Photography is sourced from Pexels and Unsplash and credited in the footer. When replacing images, update the alt text and the cover credit where appropriate. Avoid using an image whose license you cannot verify.

## Theme and accessibility

- The theme selector supports **Light**, **Dark**, and **System**. The choice is stored in `localStorage` under `blossie:theme`.
- A tiny inline script sets the theme before the first paint to prevent a flash of the wrong theme.
- System mode removes the explicit `data-theme` attribute so the operating system preference continues to apply live.
- The site includes skip links, visible focus styles, semantic landmarks, keyboard-operable dialogs and menus, reduced-motion support, and accessible labels for icon-only controls.
- The mobile menu uses the native `<dialog>` element and locks background scrolling while open.

## Search

`/search/` fetches `/search-index.json`, which is generated from the article collection at build time. Search is client-side and requires no server. It scores title, category, tag, summary, and body matches and highlights matching words in results.

The search index includes article body text, so it will grow with the journal. If the archive becomes very large, consider generating shorter body excerpts or moving to a hosted search service.

## Newsletter demo

The newsletter form is a **design demo only**. It performs no network request, has no backend, and does not store email addresses. On submit it validates the address locally, shows a demo message, and clears the form. The input intentionally has no `name` attribute so it cannot be submitted as part of a normal form post.

This is stated in the form's helper text and in the footer. If you connect a real provider later, add a server endpoint or provider form action, update the privacy copy, and remove the demo wording.

## Deployment

The journal is published with GitHub Pages at:

```text
https://temidayoxyz.github.io/
```

The canonical site URL lives in `astro.config.mjs`:

```js
site: 'https://temidayoxyz.github.io',
```

Update that value if you publish under a different domain, then rebuild so canonical links, Open Graph URLs, the RSS feed, robots.txt, and the sitemap all use the correct host.

### GitHub Pages

The public repository is `temidayoxyz/temidayoxyz.github.io`. Every push to `main` triggers `.github/workflows/deploy.yml`, which installs dependencies, runs `npm run build`, uploads `dist/`, and publishes it to Pages.

In the repository, **Settings → Pages → Build and deployment → Source** is set to **GitHub Actions**. No environment variables or secrets are required.

To deploy from a fork, enable GitHub Pages for the fork and update `site` in `astro.config.mjs` to its Pages URL.

### Other static hosts

Because the output is fully static, `dist/` can be served by Cloudflare Pages, Netlify, or any static file host. Preserve directory-style URLs (`/journal/story/` → `journal/story/index.html`) and serve `404.html` for missing paths.
